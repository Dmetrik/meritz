# 온보딩 — `/product-spec:init`

목표는 **5분 안에 `.claude/product-spec.json` 하나를 만들고 첫 문서까지 뽑는 것**이다.
설정이 길어지면 사람들은 여기서 이탈한다. 질문은 네 번이면 충분하다.

## 원칙

- **먼저 조사하고, 아는 건 묻지 않는다.** 리포를 스캔해서 알아낼 수 있는 건 추측해서
  기본값으로 제시하고, 확인만 받는다
- **"안 씀"은 정상적인 답이다.** 회사마다 툴이 다르고, 아예 없는 팀도 있다.
  연동이 하나도 없어도 이 스킬은 완전히 동작한다
- **인증은 대신 하지 않는다.** `claude mcp add` 실행과 OAuth 승인은 사용자 몫이다.
  명령어를 정확히 알려주고 기다린다
- **토큰 값을 받아 적지 않는다.** 사용자가 채팅에 토큰을 붙여넣으면 설정 파일에 쓰지 말고,
  환경변수로 넣는 방법을 안내한다

---

## 0단계: 리포 스캔 (질문 전에 먼저)

- 언어·프레임워크: `package.json`, `pyproject.toml`, `go.mod`, `build.gradle` 등
- 모노레포 여부: `packages/`, `apps/`, workspace 설정
- 기존 문서 위치: `docs/`, `documentation/`, `.github/`
- 리모트 주소: `git remote -v` (호스트로 트래커를 추정할 수 있다)
- 이미 `.claude/product-spec.json`이 있으면 **덮어쓰지 말고** 현재 설정을 보여준 뒤
  무엇을 바꿀지 묻는다

스캔 결과를 두세 줄로 요약해서 먼저 보여준다. 그래야 사용자가 "얘가 내 리포를 보고 말하는구나"를
안다.

```
Next.js 15 + Prisma 모노레포로 보입니다 (apps/web, apps/api).
문서 폴더는 docs/가 이미 있네요. GitHub 리모트를 쓰고 있습니다.
```

---

## 1단계: 문서 위치와 ID 접두어

```
스펙 문서를 어디에 둘까요?
  1) docs/specs/     (추천 — 이미 docs/가 있습니다)
  2) 직접 입력

문서 ID 접두어는 무엇으로 할까요? 예: DM-001, PAY-001
  → 기본값: 리포 이름에서 딴 대문자 약어
```

모노레포면 **어느 패키지의 스펙인지** 먼저 확정한다. 한 스펙은 한 제품을 다룬다.

---

## 2단계: 세 슬롯 인터뷰

한 번에 하나씩 묻는다. 각 슬롯마다 "안 씀"을 명시적으로 선택지에 넣는다.

### 슬롯 1 — 이슈 트래커 (`tracker`)

> 이슈·티켓 관리는 무엇으로 하시나요? 스펙 문서의 "왜 만들었는가"를 여기서 가져옵니다.
> `1) Jira  2) YouTrack  3) Linear  4) GitHub Issues  5) 안 씀`

Jira를 고르면 **Cloud인지 온프레미스(Data Center/Server)인지 반드시 되묻는다.** 공식 MCP
서버는 Jira Cloud만 지원하므로 연결 방법이 완전히 달라진다.

> Jira 주소가 `*.atlassian.net`이면 Cloud, 사내 도메인(예: `jira.회사.co.kr`)이면
> 온프레미스입니다. 어느 쪽인가요?

### 슬롯 2 — 커뮤니케이션 (`chat`)

> 팀 논의는 어디서 하시나요? 결정 배경을 가져오고, 완성된 문서를 알리는 데 씁니다.
> `1) Slack  2) 안 씀`

### 슬롯 3 — 위키 (`wiki`)

> 완성된 문서를 개발자가 아닌 분들도 보게 하려면 어디에 올려야 하나요?
> `1) Confluence  2) Notion  3) 안 씀 (리포 Markdown만)`

**"안 씀"을 고를 만한 이유를 같이 알려준다.** 리포 Markdown이 원본이고 위키는 복사본이라,
개발팀만 본다면 위키 연동은 없어도 된다.

## 3단계: 연결 안내

고른 툴의 `references/tools/<type>.md`를 읽고, 거기 적힌 **연결 명령어와 토큰 발급 위치를
그대로** 안내한다. 툴마다 다르므로 기억에 의존해 적지 말고 반드시 참고 문서를 읽는다.

안내는 이 형식으로 한다.

```
Jira Cloud 연결 — 아래 명령어를 터미널에서 실행해 주세요.

  claude mcp add --transport http atlassian https://mcp.atlassian.com/v1/mcp

그다음 Claude Code에서 /mcp 를 입력하고 atlassian을 선택해 브라우저 인증을 마치면 됩니다.
(인증은 제가 대신 할 수 없습니다. OAuth 승인 창이 뜹니다.)

끝나면 알려주세요. 실제로 읽히는지 확인해 보겠습니다.
```

이미 연결돼 있는지 먼저 확인하고, 연결돼 있으면 이 단계를 건너뛴다.

---

## 4단계: 설정 파일 작성

`assets/product-spec.config.example.json`을 기준으로 `.claude/product-spec.json`을 쓴다.
고르지 않은 슬롯은 `{"type": "none"}`으로 명시한다 — 키를 빼면 나중에 설정이 누락된 건지
일부러 안 쓴 건지 구분이 안 된다.

`.gitignore`에 넣지 않는다. **이 파일은 팀이 공유해야 하는 설정**이다. 대신 토큰 같은
비밀값은 절대 이 파일에 넣지 않고 환경변수로 뺀다.

---

## 5단계: 연결 검증

설정한 툴마다 **읽기 전용 호출을 한 번씩** 해서 실제로 되는지 확인한다.

| 슬롯 | 검증 방법 |
|---|---|
| `tracker` | 프로젝트 정보 조회 또는 최근 이슈 1건 조회 |
| `chat` | 설정한 채널 정보 조회 (메시지 전송은 하지 않는다) |
| `wiki` | 스페이스/데이터베이스 정보 조회 (페이지 생성은 하지 않는다) |

결과를 표로 보고한다. 실패해도 온보딩을 중단하지 않는다 — 나중에 고쳐도 문서 작성은 된다.

```
설정 완료 → .claude/product-spec.json

| 슬롯 | 설정 | 연결 |
|---|---|---|
| tracker | Jira Cloud (PAY) | ✅ 이슈 1건 조회 성공 |
| chat    | Slack (#product-spec) | ✅ 채널 확인 |
| wiki    | 안 씀 | — |
```

---

## 6단계: 첫 문서 제안

여기서 멈추면 안 된다. 온보딩의 목적은 설정이 아니라 **첫 문서**다.

> 설정이 끝났습니다. 지금 바로 이 제품의 스펙 초안을 만들어 볼까요?
> 코드를 읽어서 채울 수 있는 부분은 자동으로 채우고, 제가 알 수 없는 부분
> (왜 만들었는지, 누구를 위한 건지)은 질문으로 남겨 드립니다.

동의하면 `SKILL.md` §2 신규 작성으로 이어간다.

## 다른 회사에서 쓰기

이 플러그인에는 특정 회사에 종속된 값이 없다. 다른 조직에 배포하려면:

1. 마켓플레이스 저장소를 포크하고 `.claude-plugin/marketplace.json`의 `name`·`owner`를 바꾼다
2. 그 저장소를 조직의 Git 호스트에 올린다
3. 팀에 `/plugin marketplace add <저장소 URL>` → `/plugin install product-spec@<이름>`을 공지한다

제품별 설정(`docsDir`, `specIdPrefix`, 연동 툴)은 각 리포의 `.claude/product-spec.json`에
있으므로 플러그인 자체는 손댈 필요가 없다. 표준 양식을 조직 사정에 맞게 바꾸고 싶다면
`assets/SPEC_TEMPLATE.md`와 `references/spec-format.md` 두 파일만 수정하면 된다.
