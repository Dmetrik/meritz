# Notion 어댑터 (`wiki`)

**리포의 Markdown이 원본이고 Notion은 복사본이다.** Notion에서 고친 내용은 다음 발행 때
덮어써진다 — 페이지 상단에 그 사실을 반드시 적어 둔다.

---

## 연결 (`mode: "mcp"`)

```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

그다음 `/mcp` → `notion` → 브라우저 OAuth 승인. 승인 화면에서 **어느 페이지·데이터베이스에
접근을 허용할지 직접 선택**해야 한다. 여기서 스펙 문서를 둘 상위 페이지를 반드시 포함시킨다.
빼먹으면 연결은 되는데 페이지가 안 보인다 — 가장 흔한 실수다.

설정:

```json
{
  "wiki": {
    "type": "notion",
    "mode": "mcp",
    "parentPageId": "1a2b3c4d5e6f7890abcdef1234567890",
    "databaseId": null
  }
}
```

- `parentPageId` — 스펙 문서를 하위 페이지로 만들 상위 페이지
- `databaseId` — 데이터베이스로 관리한다면 여기에. 이 경우 `parentPageId`는 비운다

ID는 브라우저 주소에서 딴다. `notion.so/제목-1a2b3c4d...`의 뒤쪽 32자리 16진수가 ID다.

### 데이터베이스로 관리할 때

스펙이 여러 개면 페이지보다 데이터베이스가 낫다. 이런 속성을 미리 만들어 두면 발행 시
자동으로 채운다.

| 속성 이름 | 타입 | 채워지는 값 |
|---|---|---|
| `Spec ID` | Title 또는 Text | `DM-001` |
| `제품명` | Text | frontmatter `title` |
| `상태` | Select | `draft` / `active` / `deprecated` |
| `담당` | Text 또는 Person | frontmatter `owner` |
| `문서 버전` | Text | `1.3.0` |
| `최종 동기화` | Date | `last_synced_at` |
| `리포 경로` | URL | Git 호스트의 원본 파일 링크 |

속성이 없으면 만들지 말고 건너뛴다. 남의 데이터베이스 스키마를 임의로 바꾸지 않는다.

## 사용 — 발행

`/product-spec:publish`에서만 동작한다.

### 1. 기존 페이지 확인

frontmatter의 `wiki_url`이 있으면 그 페이지를 갱신한다. 없으면 `Spec ID`로 검색하고,
그래도 없으면 새로 만든다. **같은 스펙의 페이지를 중복 생성하지 않는다.**

### 2. 상단 안내 (필수)

페이지 첫 블록에 콜아웃으로 넣는다.

```
ℹ️ 이 문서는 acme/payment-widget 리포의 docs/specs/DM-001-payment-widget.md 에서
   자동 생성됩니다. 여기서 수정한 내용은 다음 갱신 때 사라집니다.
   최종 동기화: 2026-09-05
```

### 3. 본문 변환

- `<!-- spec:section -->` 같은 **HTML 주석은 제거한다**
- Markdown 표 → Notion 표 블록
- 코드 블록 → 언어를 지정한 code 블록
- 리포 상대 경로 링크 → Git 호스트 절대 URL
- `> ❓ 확인 필요:` → 콜아웃 블록으로 두면 눈에 띄어 답을 받기 쉽다

### 4. 갱신 방식

Notion API는 블록 단위 수정이라 부분 갱신이 까다롭다. **본문 블록을 전부 지우고 다시
쓰는 편이 안전하다.** 단, 페이지 자체는 지우지 않는다 — URL과 댓글이 살아 있어야 한다.

지우기 전에 사용자에게 알린다.

```
Notion 페이지 "결제 위젯 스펙"의 본문을 새 내용으로 교체합니다.
페이지의 댓글과 URL은 유지되고, 본문 블록만 다시 씁니다. 진행할까요?
```

### 5. 발행 후

페이지 URL을 frontmatter의 `wiki_url`에 기록한다.

## 검증

온보딩에서는 **상위 페이지 조회만** 한다. 페이지를 만들어서 확인하지 않는다.

조회가 실패하면 대부분 OAuth 승인 때 해당 페이지를 선택하지 않은 것이다.

> Notion 연결은 됐는데 지정한 페이지가 보이지 않습니다.
> Notion 우상단 `...` → **연결(Connections)** 에서 Claude를 이 페이지에 추가해 주세요.

## 자주 겪는 문제

| 증상 | 원인과 해결 |
|---|---|
| 연결은 됐는데 페이지가 없다고 나온다 | OAuth 승인 범위에 그 페이지가 빠졌다. 페이지의 Connections에 추가 |
| ID가 안 맞는다 | 주소에서 하이픈 없는 32자리만 딴다. `?v=` 뒤는 뷰 ID라 다른 값이다 |
| 데이터베이스 속성이 안 채워진다 | 속성 이름이 다르다. Notion의 실제 속성명과 대소문자까지 맞춘다 |
| 표가 텍스트로 들어간다 | 표 블록으로 변환하지 않고 Markdown 원문을 그대로 넣었다 |
