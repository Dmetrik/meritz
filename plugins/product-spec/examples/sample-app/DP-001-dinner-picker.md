# 오늘 저녁 뭐 먹지

<!-- spec:section id=summary -->
## 한 줄 요약

저녁 메뉴를 고민하는 시간을 없애 주는 한 페이지짜리 웹 도구입니다.
종류·국물·혼자 여부 세 가지 조건을 고르고 버튼을 한 번 누르면, 조건에 맞는 메뉴 24개 중
하나를 무작위로 뽑아 보여줍니다. 설치도 로그인도 없이 브라우저에서 바로 씁니다.

로그인도 역할 구분도 없습니다. 페이지를 여는 사람은 모두 같은 화면을 보고 같은 기능을 씁니다.

> 답에 따라 "혼자 먹기 좋은" 조건과 결과 복사 기능의 무게가 달라집니다.)

<!-- spec:section id=flows -->
## 3. 어떻게 쓰나

### 흐름 1 — 그냥 하나 골라 달라고 하기

1. 페이지를 열면 "아직 안 골랐습니다"라고만 적힌 빈 결과판이 보이고, 그 아래에 지금 조건에
   맞는 후보가 몇 개인지 나옵니다. 처음에는 전체 24개가 후보입니다.
2. "골라줘"를 누르면 결과판에서 메뉴 이름이 빠르게 스쳐 지나가다 멈추고, 뽑힌 메뉴의
   그림·이름·한 줄 설명이 나옵니다. 이때 결과판 테두리에 불이 들어온 것처럼 밝아집니다.
3. 다시 누르면 다른 메뉴가 나옵니다. 방금 나온 메뉴와 그 직전 두 개까지는 다시 나오지 않습니다.

**잘 안 될 때** — 조건을 좁혀 후보가 세 개 이하로 줄면 "방금 나온 메뉴는 다시 안 나온다"는
규칙이 지켜지지 않습니다. 같은 메뉴가 연달아 나올 수 있고, 후보가 하나뿐인 조합에서는 몇 번을
눌러도 매번 같은 메뉴만 나옵니다. 화면 아래 "어떻게 고르나" 설명에는 이 규칙이 언제나
지켜지는 것처럼 적혀 있어서, 사용자는 도구가 고장 났다고 느낄 수 있습니다.
동작을 줄이도록 설정한 기기에서는 스쳐 지나가는 연출 없이 결과가 곧바로 나타납니다.

### 흐름 2 — 조건을 좁혀서 고르기

1. 종류를 하나 고릅니다. 전체·한식·중식·일식·양식·분식·아시안 중에서 한 번에 하나만
   고를 수 있습니다.
2. "국물 있는 걸로"와 "혼자 먹기 좋은"을 따로 켜고 끕니다. 둘 다 켜면 두 조건을 모두
   만족하는 메뉴만 남습니다.
3. 조건을 건드릴 때마다 후보 수가 곧바로 다시 세어지고, 앞서 뽑아 둔 결과는 지워집니다.
   조건에 안 맞는 답이 화면에 남아 헷갈리지 않도록 하기 위해서입니다.

**잘 안 될 때** — 조건에 맞는 메뉴가 하나도 없으면 후보 수 자리에 "조건에 맞는 메뉴가
없습니다"라고 나오고 "골라줘" 버튼이 흐려지며 눌리지 않습니다. 지금 메뉴 구성에서 후보가
0개가 되는 조합은 **양식 + 국물 있는 걸로** 하나뿐입니다. 후보가 정확히 하나만 남는 조합은
일식·분식·아시안에 각각 국물 조건을 건 경우입니다.

### 흐름 3 — 뽑힌 결과를 남에게 알리기

1. 결과가 나오면 그 아래에 "결과 복사" 버튼이 함께 나타납니다.
2. 누르면 "오늘 저녁은 〈메뉴 이름〉 〈그림〉" 형태의 한 줄이 복사되고, 버튼 글자가 잠깐
   "복사됨"으로 바뀝니다.
3. 잠시 뒤 버튼 글자는 "결과 복사"로 돌아옵니다.

**잘 안 될 때** — 브라우저가 복사를 막으면 버튼 자리에 복사하려던 문장이 그대로 나타납니다.
사용자가 직접 읽어 옮겨 적으라는 뜻인데, 이 문장도 1~2초 뒤 "결과 복사"로 돌아가 버려서
옮겨 적을 시간이 부족합니다. 또 조건을 바꾸면 결과와 함께 복사 버튼도 사라집니다.

<!-- spec:human -->
> ❓ 확인 필요: 후보가 세 개 이하일 때 "최근 세 개는 건너뛴다" 규칙이 깨지는 것은
> 의도한 동작인가요? (억지로 규칙을 지키면 뽑을 게 없어지니 일부러 푼 것으로 보입니다.)
> 의도라면 화면 설명 문구를 실제 동작에 맞게 고쳐야 하는지도 함께 알려주세요.
<!-- /spec:human -->

## 4. 화면

화면은 하나뿐입니다. 페이지 안에서 이동하는 다른 화면이나 팝업은 없습니다.

| 화면 | 무엇을 하는 곳 | 누가 들어오나 | 여기서 할 수 있는 것 |
|---|---|---|---|
| 메뉴 고르기 (단일 페이지) | 조건을 고르고 저녁 메뉴 하나를 추천받는 곳 | 누구나. 로그인이나 권한 구분이 없다 | 종류 고르기 · 국물/혼자 조건 켜고 끄기 · 후보 수 확인 · 추천받기 · 결과 복사 · 추천 규칙 읽기 |

화면은 위에서부터 간판(제목과 한 줄 소개) → 조건 고르기 → 결과판 → 버튼과 후보 수 →
"어떻게 고르나" 설명 순으로 놓여 있습니다.

**빈 상태·오류 상태**

| 상태 | 언제 | 무엇이 보이나 |
|---|---|---|
| 아직 안 고름 | 페이지를 처음 열었을 때, 조건을 바꾼 직후 | 결과판에 "아직 안 골랐습니다". 복사 버튼은 숨겨진다 |
| 후보 없음 | 조건에 맞는 메뉴가 0개일 때 | 후보 수 자리에 "조건에 맞는 메뉴가 없습니다". "골라줘"가 흐려지고 눌리지 않는다. 결과판은 "아직 안 골랐습니다" 그대로 |
| 메뉴 목록을 못 불러옴 | 메뉴 목록 파일을 읽지 못했을 때 | 결과판에 "메뉴를 불러오지 못했습니다. 새로고침해 주세요." 조건 버튼은 아예 만들어지지 않는다 |

<!-- spec:human -->
> ❓ 확인 필요: 메뉴 목록을 못 불러온 상태에서도 "골라줘" 버튼은 그대로 눌립니다.
> 누르면 안내가 "조건에 맞는 메뉴가 없습니다. 조건을 하나 풀어 보세요."로 바뀌어,
> 사용자가 원인을 조건 탓으로 오해하고 엉뚱한 곳을 만지게 됩니다.
> 이 상태에서는 버튼을 비활성화하거나 안내를 유지하도록 고칠까요?

## 6. 안 하는 것

| 안 하는 것 | 이유 |
|---|---|
| 로그인·계정 | 인증 장치가 전혀 없다. 누구나 같은 화면을 보고 같은 기능을 쓴다 |
| 조건·결과 저장 | 새로고침하면 골라 둔 조건과 뽑은 결과가 모두 사라진다. 화면 아래에도 저장하지 않는다고 밝혀 두었다 |
| 화면에서 메뉴 추가·수정·삭제 | 메뉴 목록은 고정된 24개다. 늘리거나 고치려면 메뉴 목록 파일을 직접 손봐야 한다 |
| 종류 여러 개 동시 선택 | 종류는 한 번에 하나만 고를 수 있다. 예를 들어 "한식이나 일식"으로는 좁힐 수 없다 |
| 특정 메뉴 빼기 | 싫어하는 메뉴를 후보에서 제외하는 기능이 없다 |
| 가격·거리·식당 정보 | 메뉴 이름과 한 줄 설명만 다룬다. 어디서 먹을지는 알려주지 않는다 |
| 주문·예약·배달 연결 | 외부 서비스와 연결되어 있지 않다 |
| 추천 이력 보기 | 직전 세 개를 내부적으로 기억하지만 화면에 보여주지 않는다 |
| 여럿이 함께 고르기 | 여러 사람의 의견을 모으거나 투표하는 기능이 없다. 결과 공유는 복사해서 직접 전달하는 방식뿐이다 |
| 한국어 외 언어 | 화면 문구와 메뉴 이름이 한국어로만 되어 있다 |

<!-- spec:human -->
> ❓ 확인 필요: 메뉴 24개 고정은 MVP라서 그런 것인가요, 아니면 "고르기 쉬운 개수"로
> 일부러 제한한 것인가요? 늘릴 계획이 있다면 화면 아래 "메뉴 24개" 문구가 숫자를 직접
> 적어 둔 형태라 함께 고쳐야 합니다.

## D. 배포와 운영

- **배포 방식**: 빌드 단계가 없다. `index.html`, `src/`, `data/`를 그대로 정적 호스팅에

  되돌리는 데 제약이 없다.
- **모니터링**: 없다. 로깅, 오류 수집, 사용량 측정 장치가 모두 붙어 있지 않다.
