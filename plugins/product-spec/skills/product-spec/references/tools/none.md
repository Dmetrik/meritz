# 연동 없음 (`type: "none"`)

**연동이 하나도 없어도 이 스킬은 완전히 동작한다.** 코드베이스만으로 스펙 문서의 대부분을
채울 수 있다. 연동은 근거를 풍부하게 할 뿐, 없다고 멈출 이유가 아니다.

`"none"`은 실패가 아니라 **정상적인 선택**이다. 이렇게 안내한다 — 사용자가 뭔가 빠뜨렸다고
느끼지 않게.

---

## 슬롯별로 없을 때 무엇이 달라지나

### `tracker: none` (이슈 트래커 없음)

- 코드에서 뽑는 섹션(`flows`, `screens`, `features`, `scope` + 2부 전체)은 **영향 없다**
- `problem`, `users`는 처음부터 `spec:human` 블록 + `> ❓ 확인 필요:` 질문으로 남긴다
- `changelog`의 요약은 **커밋 메시지에서** 만든다. 이슈 키 열은 비운다

커밋 메시지가 유일한 단서이므로 조금 더 공들여 읽는다.

```bash
git log --pretty='%h %s%n%b' <from>..<to>
```

### `chat: none` (커뮤니케이션 연동 없음)

- 결정 배경을 찾을 곳이 없다. 추측하지 말고 질문으로 남긴다
- 발행 후 알림을 보내지 않는다. 대신 마지막 보고에 링크를 남겨 사용자가 직접 공유하게 한다

### `wiki: none` (위키 없음)

- `/product-spec:publish`는 아무 일도 하지 않는다. 실행하면 이렇게 알린다

  > `wiki` 연동이 설정되어 있지 않습니다. 스펙 문서는 `docs/specs/`의 Markdown이 원본이며,
  > 그대로 PR에서 리뷰하실 수 있습니다. 위키 발행이 필요해지면
  > `/product-spec:init`에서 Confluence나 Notion을 추가할 수 있습니다.

- 개발팀만 문서를 본다면 이 상태가 오히려 낫다. 원본이 하나뿐이라 동기화 문제가 없다

---

## 나중에 추가하기

`/product-spec:init`을 다시 실행하면 기존 설정을 보여주고 바꿀 부분만 물어본다.
설정 파일을 직접 고쳐도 된다.

```json
{
  "integrations": {
    "tracker": { "type": "none" },
    "chat":    { "type": "none" },
    "wiki":    { "type": "none" }
  }
}
```

---

## 연동이 있는데 실패했을 때

설정은 `none`이 아닌데 호출이 실패한 경우 — 인증 만료, 네트워크, 권한 문제 등 —
**작업을 중단하지 않는다.** 연동 없이 진행하고, 마지막 보고에 한 줄로 남긴다.

```
⚠️ Jira 조회 실패 (401). 문서는 코드 근거만으로 작성했습니다.
   /mcp 에서 atlassian 재인증 후 /product-spec:update 를 다시 실행하면 배경이 채워집니다.
```

문서를 못 만드는 것보다 근거가 조금 부족한 문서가 낫다. 다만 **무엇이 빠졌는지는 반드시
말한다.** 조용히 넘어가면 사용자는 완전한 문서라고 믿는다.
